# Sprint 10 Field validation and release

Read `docs/completion-plan/README.md` first.

Do not add features during the first observation pass.

Run three uncoached sessions on the lowest-end supported Android device:

## Reception

Give the agent producer and fruit facts. Interrupt the application and network once. The user must resume, understand saved-on-phone versus sent, and create no duplicate.

## Production and quality

Start from an eligible reception. Record production, quarantine one test lot, and resolve it. The worker must always identify the next action; ADMIN must see the latest result once.

## Sale

Request mixed formats, an optional customer, and partial payment without mentioning production lots. The salesperson must choose products naturally, avoid overselling, understand payment state, and create one sale.

Record pauses longer than five seconds, labels requiring explanation, exit attempts, synchronization understanding, cross-device delay, and ignored guidance.

After observation, propose only evidence-backed fixes. Run typecheck, lint, all tests, Expo web export, and the device regression suite. Produce a final go-live recommendation with deferred capabilities and known limits.
