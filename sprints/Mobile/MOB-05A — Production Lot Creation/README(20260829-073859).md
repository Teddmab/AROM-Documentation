## Objective

Allow an authorized Production & stock user to transform available received raw material into one production lot online or offline, with drafts, source traceability, safe calculations and exactly-once synchronization.

## Before implementation

Inspect and document:

- The real `Production`/lot schema in mobile and AROM-Production.
- Firestore rules and permitted production/stock writes.
- Existing web-dashboard production creation and calculations.
- How available raw material, finished products, bottles, losses and stock are currently represented.
- Whether creation uses one document, a batch, transaction or several client writes.

Reuse confirmed fields and business rules. Do not create a parallel mobile production model.

## Entry points

- Production & stock home → `Lancer une production`.
- Production queue/list → `Nouvelle production`.
- Contextual `+` → `Nouvelle production` when authorized.

- Show the AROM identity, back control when applicable, page title/context, `Mode Production & stock`, synchronization state and notification access.

## Complete flow

### 1. Production list/queue

- Show real productions newest first with supported status and sync state.
- Separate local drafts/pending records from synchronized lots.
- Primary action: `Nouvelle production`.
- Search/filter only using real fields.

### 2. Select source reception or raw-material stock

- Show only sources that existing rules consider usable/available.
- Display source ID/date, producer, material and confirmed available quantity.
- Allow multiple source receptions only if the real model supports it.
- Never infer availability by subtracting incomplete cached values when the domain already provides a canonical calculation.

### 3. Raw material used

- Enter quantity used with the real unit/precision.
- Validate greater than zero and no more than confirmed available quantity.
- Show remaining quantity as an informative calculation.
- If source availability is stale/offline, show last-sync time and revalidate before remote commit.

### 4. Output obtained

- Capture the real output measure supported by the model, for example juice volume or finished quantity.
- Use large numeric controls and clear unit labels.
- Do not assume litres if the real schema uses another field/unit.

### 5. Packaging/finished units

- Capture supported bottle/product formats and quantities.
- Use existing product/catalog/packaging records.
- Validate that packaged output matches the real conversion rules.
- If packaging is not part of the production schema, do not invent it; document and adjust the screen.

### 6. Consumables and losses

- Show supported ingredients/consumables only.
- Calculate yield/loss automatically from confirmed inputs and outputs using existing domain helpers.
- Do not ask workers to calculate percentages manually.
- Explain unusual loss with a note only when the existing model supports one.

### 7. Review

- Summarize source reception(s), raw material used, output, packaged units, consumables and calculated yield/loss.
- `Modifier` returns to the relevant step without losing values.
- Primary action: `Créer le lot de production`.

### 8. Result/detail

- Online: show created lot ID and synchronized state.
- Offline: `Enregistré sur cet appareil` with pending dependency/sync explanation.
- Show traceability from source reception to production lot.
- Actions: `Voir le lot`, `Nouvelle production` and later `Contrôler la qualité` only if that route exists.

## Draft lifecycle

- Explicit `Enregistrer comme brouillon` on every wizard step.
- Auto-save meaningful changes using the existing versioned local-draft pattern.
- Draft list/filter, exact-step resume, safe delete and restart recovery.
- Drafts do not consume raw material or affect stock/metrics.
- Final submission converts the stable draft ID into exactly one queued/synchronized production lot.

## Offline and dependency rules

Extend the existing shared mutation queue:

- Stable client-generated production ID.
- A production depending on a locally created/pending reception uses `dependsOn` and remains blocked until that reception is synchronized.
- Preserve the dependency chain producer → reception → production.
- Revalidate source availability before remote commit.
- If another production consumed the source first, move to a conflict state; never silently create negative stock.
- Retry after restart/connectivity changes without duplicate lots.
- Keep the local record until server acknowledgement.

## Atomicity and stock integrity

- Follow the existing web-domain transaction/batch behavior exactly.
- Raw-material deduction, production creation and finished-output addition must succeed atomically when they are one business operation.
- Never update stock optimistically as synchronized before acknowledgement.
- If existing infrastructure cannot guarantee atomic production/stock updates, stop and report the blocker instead of shipping partial writes.
- The mobile client must not become authoritative for security-sensitive totals.

## Permissions

- Only users with confirmed production permission may create a lot.
- Stock-only permission must not grant production creation automatically.
- Revalidate permission before enqueue and before sync.
- Firestore rules must restrict unsafe/immutable/audit fields.

## Required states

- Loading/empty production list
- No usable source reception
- Source cache stale/offline
- Insufficient available quantity
- Validation error
- Draft saved/resumed/deleted
- Submission in progress
- Dependency blocked
- Local save successful
- Sync failed/retry
- Source availability conflict
- Permission/session expired
- Partial evidence/catalog data unavailable

## Visual and accessibility

- Persistent `Mode Production & stock` chip on every screen/modal.
- Persistent shared top menu and bottom menu on every screen; wizard progress belongs below the top menu.
- AROM cream/green system; yellow for pending/warnings; red for blocking errors.
- One decision per step, short French wording, wizard progress and sticky primary action.
- Large numeric controls, clear units, screen-reader labels and 48px targets.
- Use a dedicated reusable pineapple/product asset if available; do not crop the design mockup into an application asset.

## Acceptance criteria

- User can create and inspect one production lot online or offline.
- Source reception and quantities remain traceable.
- Draft survives restart and has no stock effect before submission.
- Offline dependency chain synchronizes in order exactly once.
- Yield/loss uses confirmed existing logic.
- No production can create negative or double-counted stock.
- Existing MOB-01–MOB-04B behavior remains green.
- Automated component/navigation tests confirm the top and bottom menus render on the production list, every wizard step, result/detail and representative error/loading states.

## Tests and verification

## Out of scope
